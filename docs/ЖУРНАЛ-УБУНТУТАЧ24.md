## 0. Как загрузчик находит `rootfs.img` (общее для обоих экспериментов)

Образ ядра `boot_v234_panel_asleep_dark.img` (ядро #422, ramdisk v233) при старте ищет `rootfs.img` в таком порядке и берёт ПЕРВЫЙ найденный:

1. SD-карта (любой `mmcblk*`, файл `rootfs.img` в корне);
2. USB-флешка по OTG (`sd*`, только пока телефон в режиме host);
3. **`/data` = раздел `userdata`** (`/dev/block/by-name/userdata`, ext4, корень раздела; на работающей системе это `/mnt/userdata`);
4. раздел `system` (как обычно: GPT-образ postmarketOS из прошивки).

`rootfs.img` принимается в двух форматах: **GPT-образ pmbootstrap** (p2 с меткой `pmOS_root`, секторы 4096) или **голый ext4** (оба наших
эксперимента — голый ext4). Для голого ext4 `M52XQ_NO_RESIZE=1` (образ не растягивается), а `/boot` берётся из образа в `system`.
Исходники хука: `архив/в40/initramfs-src/00-map-dynparts.sh.v233`, `init_2nd.sh.v233`.

**Откат любого эксперимента:** переименовать/убрать `/data/rootfs.img` (из TWRP: `/data` — обычная ext4 на `sda34`). Загрузка вернётся к
postmarketOS из раздела `system`.

## 2. Этап 2 — postmarketOS + Lomiri без Halium (папка `002`)

### Идея
Lomiri — обычная Wayland-оболочка (композитор Mir). Halium нужен только Ubuntu-сборке «для Android-устройств». В postmarketOS есть
готовый пакет `postmarketos-ui-lomiri` (pmaports/main, «Wayland, convergent desktop, Experimental»). Зависимости: `lomiri`, `lomiri-system-settings`,
`lomiri-notifications`, `lomiri-location-service`, `hfd-service`, `repowerd`, `sensorfw`, `superd`, `bluez`, NetworkManager, elogind-варианты и т. д.
У нас на mainline уже работают GPU (Mesa/Freedreno на Adreno 660), сенсор, звук, Wi-Fi/BT, ModemManager, датчики.

### Проверка установки (`apk add --simulate postmarketos-ui-lomiri` на телефоне, система не менялась)
* 222 операции: **193 новых, 29 обновлений, 0 удалений, 0 конфликтов**;
* обновляются общие библиотеки (openssl, libx11, util-linux, ncurses) и **mesa 26.2.3 → 26.2.5**; Qt6/KDE/systemd/NetworkManager/ModemManager не трогаются;
* `lomiri` ≈ 8 МБ, остальное — Qt5 и индикаторы.
* **Проблема: в корне работающей системы свободно всего 903 МБ из 5,8 ГБ** — Lomiri туда не помещается. Поэтому делаем отдельный образ.

### Как делаем образ (в процессе)
1. `002/rootfs.img`: пустой ext4 **8 ГиБ**, метка `pmOS_root` (`truncate -s 8G`, `mkfs.ext4 -L pmOS_root`).
2. **Копия корня работающего телефона** (чтобы остались прошивка модема, BT-адрес, реестр датчиков, наши службы и патчи — всё, что установщик
   берёт с телефона при прошивке):
   `ssh root@172.16.42.1 'cd / && find . -xdev -print0 | cpio -0 -o -H newc' | sudo cpio -idmu --no-absolute-filenames` (в смонтированный образ).
   `busybox tar` на телефоне не умеет xattr, поэтому `cpio`; проверено: файлов с `security.capability` нет (только 7 журнальных ACL в
   `/var/log/journal`), потерь нет. Каталоги `/home/user`, `/var/log`, `/var/cache/apk` (отдельные mount-ы с `userdata`) не копируются:
   в новом образе они приходят теми же bind-mount-ами из `/mnt/userdata` (то есть ваши данные те же).
3. `chroot` в образ через `qemu-aarch64` (binfmt есть): `apk add --no-cache postmarketos-ui-lomiri` (рекомендации — по месту).
4. Служба запуска Lomiri по образцу `plasma-mobile.service` (на телефоне нет `tinydm`, Plasma стартует своей службой
   `plasma-mobile.service`, `Alias=display-manager.service`, `ExecStart=/usr/bin/startplasmamobile`, `User=1000`, `PAMName=login`, `TTYPath=/dev/tty1`).
   По умолчанию остаётся Plasma; переключение — включить одну службу вместо другой.
5. `e2fsck`, md5, заливка на телефон `gzip -1 -c rootfs.img | ssh … 'gunzip > /mnt/userdata/rootfs.img.part && mv …'`.

### Ожидаемые подводные камни
* Lomiri и Plasma используют разные фоновые службы (`sensorfw`/`repowerd`/`hfd-service` против `iio-sensor-proxy`/`powerdevil`/наши службы датчиков)

* Телефония у Lomiri своя (`lomiri-telephony-service`), у нас ModemManager; наши патчи звонилки/шторки Plasma к ней не подходят.
* Нужно проверить Mir на нашей графике (Adreno 660, `msm` DRM).

## Панелей нет: заглушка LightDM (2026-10-24, ночь)

Причина: в сборке Lomiri из Alpine нет нативного модуля `LightDM.IntegratedLightDM`
(в образе Ubuntu Touch из 001 он есть, но это библиотека под glibc, на musl не загрузится).
Из-за этого `Greeter/IntegratedLightDMImpl.qml` не создавался, `LightDMService.*` был null,
и оболочка не строилась (на экране оставались только обои).

Что сделано (чистый QML, без нативного кода):
- `002/extra-files/usr/lib/lomiri/qml/LightDM/IntegratedLightDM/` — `qmldir` и синглтоны
  Greeter, Infographic, Prompts, Sessions, SessionRoles, Users, UserRoles.
  Greeter: `authenticated: true` (пароля на телефоне нет, экран входа не блокирует),
  один пользователь `user` (uid 10000), одна сессия `lomiri`.
  Роли (`Prompts.Message`, `UserRoles.NameRole`, …) сделаны через `enum`: QML не допускает
  свойства с заглавной буквы.
- Установлено на телефон, `m52xq-lomiri.service` перезапущен: ошибка «module LightDM.IntegratedLightDM
  is not installed» исчезла.
- `/home/user/.config/lomiri/wizard-has-run` создан (копия из /etc/skel): мастер первого запуска
  требует модуль `Lomiri.SystemSettings.Update`, которого нет ни в одном пакете.
  Ошибка про модуль пропала.

Остаётся в журнале: `Shell.qml:685 Unable to assign PanelState_QMLTYPE_x to PanelState_QMLTYPE_y`.
Причина: Lomiri грузит оболочку по URL `file:///usr/share/lomiri//Shell.qml` (двойной слэш),
а Panel.qml подключает `Components/PanelState` через `../../../`, то есть по нормализованному пути.
Qt считает это двумя разными модулями, и тип PanelState получается дважды. Решение ещё не выбрано.
Замечание: команда `lomiri --help` запускает второй экземпляр оболочки, её нельзя вызывать на живом телефоне.
